How I get the numbers

No themes. No plugins. No bloat.

WordPress with a page builder weighs in around 2–3 MB before you've written a word. My sites land around 60–100 KB total — the difference is hand-coded HTML, no framework, and no plugins quietly loading megabytes you didn't ask for.

  • Hand-coded HTML & CSSNo theme to inherit. No page-builder runtime. The browser parses small, predictable code — fast.
  • System fonts or one carefully chosen webfontWebfonts are the silent killer. I subset and preload what's needed, swap nothing else in.
  • Images that earn their placeWebP/AVIF, properly sized, lazy-loaded below the fold. A hero image at 40 KB, not 400.
  • Minimal JavaScriptIf a feature can be CSS, it's CSS. JS only where it earns its keep, and never a 200 KB analytics library.
  • HTTP/2 and edge cachingHosted on Vercel's edge network: served from the data centre nearest your visitor, never further.
  • Real Core Web Vitals testingEvery launch tested on a throttled mobile connection. If it's not fast on a tired phone in a bad signal, it's not fast.
How it works

Speed by design, not by audit.

01 — Build clean

Start with hand-coded HTML and a single small stylesheet. No framework debt to pay down later.

02 — Optimise assets

Every image, every font, every byte vetted. If it doesn't earn its weight, it doesn't ship.

03 — Edge hosting

Vercel global edge network. Your site loads from the closest data centre to every visitor, with HTTP/2 and aggressive caching.

04 — Measure & verify

Lighthouse and Core Web Vitals tested on launch and re-tested on every change. Real numbers, not "feels fast".
